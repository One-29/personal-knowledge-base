> 记录 M5 界面的设计目标、token 系统与关键决策。前端技术选型为**原生 HTML/CSS/JS + FastAPI 静态挂载**（零构建，02 §3）。

## 1. 设计目标（brief）

| 项 | 内容 |
|---|---|
| 产品 | KnowBase：自托管个人知识库问答（RAG + 溯源 + 拒答） |
| 使用者 | 笔记主人（学生/研究者）；答辩时评委旁观演示 |
| **主要任务** | **提问 → 看到带出处的回答 → 回到原文核对** |
| 次要任务 | 管理知识库与文档（导入、查看状态、重传、删除）；发起跨文档综合任务 |

**关键判断**：「核对」是这个产品的核心动作，不是「聊天」。界面结构必须让核对成为**一眼可见、一次点击即可完成**的动作。

## 2. 设计方向：纸面与边注

从主题的物质形态出发——笔记与知识库的现实对应物是**手稿与文献**，学术排版的三层结构恰好映射产品的三层信息：

```text
正文          ←→  回答
上标引文编号   ←→  [n] 引用标注
页边注        ←→  原文段落（溯源）
```

因此界面隐喻定为「**纸面（paper）+ 页边注（margin）**」：内容是一份可读的文档，原文显示在常驻的右侧边注栏。

## 3. Token 系统

**颜色（6）**

| 变量 | 值 | 用途 |
|---|---|---|
| `--paper` | `#EFEFEB` | 纸底（冷中性，刻意避开暖米色套路） |
| `--ink` | `#191A1C` | 正文墨色 |
| `--ink-2` | `#5B5F65` | 次级文字（说明、时序、检索用语） |
| `--rule` | `#D6D3CB` | 分组细线 |
| `--stamp` | `#93262A` | **印章红：整页唯一高饱和元素**（引用编号、拒答标记、待核对提示） |
| `--ledger` | `#2B4741` | 索引墨绿：仅用于状态（就绪）与边注栏标题 |

**字体（2 族，分工明确）**

- 正文与标题：衬线（`Source Han Serif SC / Songti SC / Georgia`）——文档与引文气质
- 编号与数据：等宽（`ui-monospace / Menlo / Consolas`）——**只用于确有语义处**：引用编号、字符偏移、状态值、会话 id、检索用语

**排版**：正文 17px / 行高 1.78（衬线行高略大）；行长上限 66ch；标题 26/19px；小注 13px。

**布局**

```text
┌──────────────────────────────────────────────┬──────────────────────┐
│  KnowBase          问答 · 工作流 · 文档 · 知识库 │                      │
├──────────────────────────────────────────────┼──────────────────────┤
│  [问题输入]                             [提问] │  原文核对            │
│                                              │  tcp.md · 偏移 89–153│
│  问：TCP 为什么需要三次握手？                 │                      │
│     三次可以确认双方的发送与接收能力¹。       │  两次只能确认客户端  │
│     两次只能确认客户端…²                     │  的发送能力与服务端  │
│                                              │  的收发能力，无法…  │
└──────────────────────────────────────────────┴──────────────────────┘
              正文栏 66ch（左对齐）                 边注栏 300px（常驻）
```

左对齐（不居中）：读-核对是线性扫描路径，居中断开视线回扫。窄屏（≤900px）时边注折到正文下方并加分隔线。

## 4. 关键设计决策

### 决策 FR1：原文显示在常驻边注栏，而非弹窗/抽屉

- **决策**：桌面端右侧 300px 边注栏常驻；点引用编号在该栏切换原文段落（淡入 180ms）。
- **备选**：点击引用弹窗/抽屉（含遮罩）。
- **理由**：核对是核心动作——边注常驻意味着「原文一直在场」，用户可连续核对多条引用而不反复开关；弹窗会打断阅读流、遮住正文。
- **代价**：占去右侧 300px（窄屏需折行处理）；移动端退化为下方区块。

### 决策 FR2：问答是连续文档流，零卡片

- **决策**：问答条目以细线分隔的文档段落呈现，无卡片、无阴影、无圆角。
- **备选**：卡片列表（每条问答一张圆角卡片 + 阴影）。
- **理由**：卡片会把连续阅读切碎，并让层级完全依赖"盒子"；文档流更贴近"读手稿 + 核对"的实际行为，层次靠字号与留白表达。
- **代价**：条目边界比卡片弱，需要靠分隔线与间距维持秩序。

### 决策 FR3：等宽字体只用于确有语义的字段

- **决策**：引用编号、字符偏移、状态值、会话 id、检索用语用等宽；其余一律衬线。
- **备选**：用等宽做小标签/装饰（如区段标签、时间戳、按钮附注）。
- **理由**：等宽在这些字段上表达"精确、可核对"的语义；作为装饰则会滑向通用模板感。
- **代价**：视觉对比度低于"到处用等宽"的做法，需要在排版上更克制。

## 5. 会话与中断（M5 交互能力）

### 决策 FR4：会话记录保存在浏览器本地，服务端保持无状态

- **决策**：会话列表与每一轮问答存 `localStorage`（新建/切换/删除），追问时把最近 6 轮随请求回传给后端，用于指代句改写。
- **备选**：服务端落库（新增 conversations/messages 表）；或仅进程内会话（D5 原方案）。
- **理由**：进程内会话刷新即丢上下文；落库引入新表与迁移，而个人自托管场景下"记录属于用户设备"更简单；前端持有后**服务端无需任何会话状态**。历史只用于改写检索用语，不参与拒答判定与引用校验，防篡改面收敛。
- **代价**：历史由客户端提供（可信度低于服务端）；换设备不同步（V1.0 若需要，改为服务端表）。

### 决策 FR5：请求进行中可停止

- **决策**：提问/任务请求进行时显示「停止」，点击用 `AbortController` 中断等待；被停止的问题不写入会话记录。
- **备选**：不提供中断（同步请求只能等）；或改服务端 SSE 流式输出。
- **理由**：LLM 生成可能耗时数秒到数十秒（Agent 任务更久），用户需要"我不想等了"的出口。前端中断即时生效（后端可能仍在跑完这次生成，但用户已脱离等待）。
- **代价**：不是真正的服务端取消（后端算力仍消耗）；若要真中断需改 SSE 流式 + 断连感知，列为 V1.0。

## 6. 明确规避的默认套路

| 套路 | 规避方式 |
|---|---|
| 暖米底 + 陶土强调 | 用冷中性纸底 + 印章朱红 |
| 近黑底 + 单一荧光强调 | 不用深色主题 |
| 圆角卡片 + 统一阴影 + 渐变装饰 | 零卡片、零阴影、零圆角 |
| 全大写标签 / `·` 连接 / `→` 结尾 | 中文标题直接写；不使用装饰性连接符 |
| 每个区块滚动入场 + 卡片 hover 位移 | 唯一动效：切换引用时边注淡入（响应动作）；尊重 `prefers-reduced-motion` |

## 7. 质量底线

响应式（≤900px 单列 + 边注折行）· 键盘可达（引用编号可 Tab 聚焦、Enter 打开，`:focus-visible` 可见轮廓）· 色彩对比（纸底/墨色 ≥ 12:1，印章红仅用于非纯文本信息）· 空态给出下一步动作（"上传一篇 Markdown 笔记…"）。

## 8. 自我批评与后续

- **已知不足**：边注栏一次只显示一条引用，跨引用对照（同时看 [1] 与 [3]）需要来回点击——后续可支持"钉住"多条（代价：边注栏空间）。
- **待验证**：真实笔记（长文档）下的边注段落长度可能过长，需要截断 + "展开全文"；当前未做截断。
- **文案**：全部界面文案使用主动语态与用户语言（"提问"→出现回答；失败信息说明发生了什么）。
