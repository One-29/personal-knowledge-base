> KnowBase 的主要任务是“从自己的资料提问，得到带出处的回答，再回到原文核对”。v0.4 统一了导航、视觉、请求状态、回答排版、文档管理和空状态；v0.6 在保持界面行为和无前端运行时框架的前提下，把单文件 JavaScript 迁移成可类型检查、可测试、可拆包的 TypeScript 架构。

## 1. 优化目标与必要性

v0.3 已经覆盖五个业务入口，但桌面宽屏存在大面积无意义空白，导航和操作权重偏低；普通问答与工作流虽然可以并发，运行状态却只显示在各自输入区，切换页面后不容易判断任务是否仍在执行；文档列表也缺少统计、筛选和明确的错误语义。

P0 优化聚焦以下结果：

1. 用户进入页面后能立即分清问答、工作流、关联图、文档和知识库。
2. 任意页面都能看见普通问答与工作流的独立运行状态。
3. 加载、空数据、错误、中断和完成都有明确反馈。
4. 回答中的标题、列表、代码、公式文本与引用具有稳定层级。
5. 点击引用后，正文与原文可以同时查看；文档列表也能直接打开完整原文。
6. 1440px 桌面、紧凑桌面、平板和 390px 手机宽度都可操作。

## 2. 技术栈与架构边界

前端使用 **HTML5 + CSS3 + 严格 TypeScript**。Vite 负责开发服务器与生产打包，Vitest 运行不依赖浏览器的模块测试；不引入 React/Vue 等运行时框架、字体 CDN 或运行时第三方脚本。生产环境中 FastAPI 只挂载 `frontend/dist`，不直接暴露 TypeScript 源码。

| 层 | 技术 | 用途 |
|---|---|---|
| 页面语义 | HTML5 | `nav`、`main`、`section`、`aside`、`form` 与 ARIA live region |
| 视觉系统 | CSS Custom Properties | 颜色、间距、圆角、宽度和字体 token |
| 布局 | CSS Grid + Flexbox | 三栏研究工作台、响应式导航、表格与工具栏 |
| 响应式 | Media Queries | 1260px 紧凑导航、1020px 原文抽屉、720px 顶部图标导航 |
| 请求 | Fetch API + ReadableStream | 调用 `/api/v1`；统一解析 JSON 错误与 POST SSE |
| 中断 | AbortController | 普通问答与工作流各自中断浏览器等待 |
| 本地状态 | localStorage | 会话、活动会话、原文栏宽度与展开偏好 |
| 图形 | Canvas 2D | 零依赖力导向关联图 |
| 类型与构建 | TypeScript strict + Vite | 编译期核对 DOM、API 契约与模块依赖，生成带内容哈希的生产资源 |
| 单元测试 | Vitest | 会话持久化、非可信本地数据与纯渲染逻辑 |
| 静态验证 | pytest + FastAPI TestClient | 生产页面与哈希资源可访问、源码挂载点完整且唯一 |

前端只渲染 API 返回的拒答、引用、步骤状态和文档状态，不在浏览器重复实现检索阈值、引用校验或工作流业务规则。

源码边界如下：

| 模块 | 职责 |
|---|---|
| `api.ts` / `types.ts` | REST 底层调用、统一错误与契约类型 |
| `sse.ts` / `ask-stream.ts` | 任意网络分片下还原 SSE 帧、校验问答事件并交付增量/最终结果 |
| `state.ts` / `conversations.ts` | 短期运行状态与经过运行时校验的本机会话 |
| `navigation.ts` | 视图元数据、hash 导航和视图生命周期 |
| `library.ts` | 知识库 CRUD、文档列表、上传、重传与轮询 |
| `tasks.ts` | 问答/工作流请求编排与会话写回 |
| `task-runtime.ts` / `task-rendering.ts` | 独立运行状态、输入框行为和契约结果渲染 |
| `evidence.ts` | 引用、历史快照、完整原文及原图核对 |
| `graph.ts` | 关联图请求、布局、绘制和交互 |
| `main.ts` | 初始化与模块装配，不承载业务实现 |

依赖通过 `package-lock.json` 固定。`scripts/build-frontend.ps1` 以锁文件摘要判断是否需要 `npm ci`，再以源码树摘要决定是否需要构建；因此 GitHub 新克隆、包含中文/空格的本机路径与日常重复启动使用同一条入口。Node.js 是构建依赖，构建后浏览器端仍只有标准 HTML/CSS/ES modules。

## 3. 页面架构

桌面端采用三栏研究工作台：

```text
┌──────────────┬────────────────────────────────────┬──────────────────┐
│ 功能导航      │ 当前视图标题、内容与操作              │ 原文核对          │
│              │                                    │                  │
│ 问答          │ 回答 / 工作流 / 关联图 / 文档 / 库    │ 可固定多条引用     │
│ 工作流        │                                    │ 可查看完整文档     │
│ 关联图        │                                    │                  │
│ 文档          │                                    │                  │
│ 知识库        │                                    │                  │
│              │                                    │                  │
│ 服务与任务状态 │                                    │                  │
└──────────────┴────────────────────────────────────┴──────────────────┘
```

- 左栏固定展示五个功能入口、本机服务状态，以及问答和工作流的两行独立状态。
- 中栏顶部展示当前视图名称和用途；URL hash 保存当前视图，可刷新或直接打开 `#docs`、`#map` 等入口。
- 右栏保留“答案正文 + 原文核对”的核心结构，可拖动调整宽度，也可收起。
- 1020px 以下右栏改为按需打开的覆盖抽屉，并默认收起，避免遮住移动端正文。

## 4. 视觉系统

界面使用低饱和冷灰画布、白色内容面、深墨绿主色和少量印章红。控件采用系统无衬线字体，回答与原文使用衬线字体，使操作与阅读形成稳定区分。

| Token | 值 | 用途 |
|---|---|---|
| `--canvas` | `#f4f5f2` | 应用背景 |
| `--surface` | `#ffffff` | 主要内容面 |
| `--ink` | `#182522` | 主文字 |
| `--ink-soft` | `#52615d` | 说明与次级信息 |
| `--line` | `#dbe2de` | 分隔与边界 |
| `--primary` | `#173f3d` | 导航、主按钮、图节点 |
| `--accent` | `#ad4a3c` | 引用、页面英文索引、注意状态 |
| `--success` | `#2c6b55` | 可检索与完成 |
| `--warning` | `#9a6421` | 等待处理与材料不足 |
| `--danger` | `#a63e36` | 请求失败与处理失败 |

阴影只用于输入坞、工具栏和主要内容面之间的层级，不参与业务状态表达。状态同时使用文字、颜色和圆点，避免只依赖颜色。

## 5. 问答、引用与工作流

### 5.1 问答

- 空会话展示产品说明和三个高等数学演示问题，点击后只填入输入框，由用户决定是否发送。
- `Enter` 发送，`Shift + Enter` 换行；输入框按内容自动增高。
- 检索与 L1 判定期间显示等待说明和真实经过秒数；收到 `metadata` 后提示检索完成，首个 `delta` 到达即切换为逐段回答。
- 增量正文标注“正在生成 · 完成后校验引用”，使用轻量富文本渲染但不把 `[n]` 变成可点击来源；最终 `result` 到达后整体替换为经过 L2 校验的回答/拒答，再绑定引用并写入本地会话。
- `sse.ts` 按行增量解析，支持 CRLF、注释、多 data 行和任意字节分片；`ask-stream.ts` 要求流中恰有一个最终结果，未知、损坏、重复或截断事件都作为明确错误处理，不保存半成品。
- 结果显示引用数量、耗时、查询改写和拒答原因。
- 回答经“先转义、后格式化”的轻量渲染器处理，支持标题、段落、有序/无序列表、引用块、代码块、行内代码和公式文本；不执行回答中的 HTML。
- 回答下方汇总引用文档，正文编号和来源按钮均可打开右侧原文。

### 5.2 原文核对

- 同一来源块去重；再次点击会滚动到已打开材料并高亮对应引用。
- 多条引用可同时固定，计数同步显示在顶栏与右栏。
- 文档管理页的“查看”会在同一区域打开完整原文。
- 后端按 Python 字符位置返回图片出现区间；前端用 Unicode code point 切分文本，在对应位置插入原图 DOM。同一图片多次引用按出现序号分别呈现，点击打开不可变版本原图，不使用 canvas 或客户端转码。
- 移动端点击引用时才打开抽屉；进入页面时不会用抽屉遮住内容。

### 5.3 工作流与并发状态

- 普通问答与工作流继续维护各自的 `AbortController` 和提交锁，同类请求一次只运行一个，两类请求可以同时运行。
- 左栏为两类任务分别显示 `运行中 mm:ss`，对应导航入口也显示脉冲圆点；切换视图后状态仍可见。
- 工作流仍使用同步接口，等待区明确说明会在完成后一次返回结果；它与普通问答的 SSE 请求保持独立控制器。
- 完成结果使用时间线展示目标、检索语句、`answered / insufficient / error` 状态、分步结论与引用，最后单独显示综合结论。
- 点击“停止等待”只中断浏览器等待，界面明确提示服务端已经发出的模型调用仍可能继续。

## 6. 文档、知识库与关联图

文档页新增总数、可检索、处理中和需留意四项统计，并提供标题搜索、状态筛选、手动刷新、上传、重传、删除和完整原文预览；表格同时显示块数和图片出现数。上传控件接受 `.md/.txt/.zip`，ZIP 的具体结构由后端统一校验。`pending / processing` 文档会在状态徽标下显示服务端持久化的校验、读取、切分、索引生成或发布阶段及确定百分比；纯映射收敛在 `ingest-progress.ts`，不根据经过时间伪造进度。页面每 2.2 秒自动刷新，完成或离开文档页后停止。存在旧块的重传失败文档仍为 `ready`，界面显示“当前旧索引仍可使用；上次更新未完成”，避免把“可以检索”和“最近更新成功”混为一件事。

知识库页把创建表单和已有知识库并列展示。每个库显示说明、文档数量和“管理文档”入口；点击后会带着对应知识库进入文档页。

关联图保留四档阈值和 Canvas 力导向布局，新增加载遮罩、图例、统计与内联错误。力模拟收敛或页面隐藏后停止 `requestAnimationFrame`，拖动节点或重新进入页面时恢复，避免静止图仍持续占用主线程。

## 7. 状态、可访问性与验证

- 本机服务通过 `/ready` 同时检查 API 与数据库，并显示已连接或未连接；`/health` 仅用于进程存活检查。
- 关键动态区域使用 `aria-live`；图标按钮、引用和表单控件具有可读名称。
- 所有可操作元素保留 `:focus-visible`，引用支持 Enter 与空格键。
- `prefers-reduced-motion` 会关闭非必要动画。
- 手机布局经过 390×844 检查，页面无水平溢出，五个导航入口均保留。
- 自动化浏览器验证覆盖结构化回答、打开真实引用、问答与工作流同时在途、两项结果分别写回会话，以及移动端原文栏默认收起。
- TypeScript 使用 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 和 `noUnused*`，CI 不允许带类型错误构建。
- Vitest 覆盖损坏的 localStorage 数据、会话删除与在途结果竞争、历史轮数上限、SSE 任意分片/截断/错误等纯逻辑边界。
- pytest 读取 TypeScript 源码，核对每个静态 `byId` 挂载点在 HTML 中存在且唯一；同时通过 FastAPI 请求实际构建出的带哈希 JS/CSS 和图标。

## 8. 后续边界

普通问答已经通过 SSE 降低模型生成阶段的空白等待，同步 `/ask` 仍保留兼容。工作流尚未逐步推送真实进度；停止也不等于可靠的服务端取消。若后续把工作流改为任务队列，应为每个步骤提供持久任务 ID、进度事件与阶段取消检查。会话仍保存在当前浏览器，跨设备同步和多 worker 持久化属于后续版本。
