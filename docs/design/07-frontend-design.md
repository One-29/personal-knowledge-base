# 07-前端界面设计（v0.4）

| 字段 | 内容 |
|---|---|
| 状态 | P0 体验优化已实现 |
| 版本 | v0.4 |
| 日期 | 2026-09-14 |

> KnowBase 的主要任务是“从自己的资料提问，得到带出处的回答，再回到原文核对”。v0.4 在不增加构建步骤和运行依赖的前提下，统一了导航、视觉、请求状态、回答排版、文档管理和空状态。

## 1. 优化目标与必要性

v0.3 已经覆盖五个业务入口，但桌面宽屏存在大面积无意义空白，导航和操作权重偏低；普通问答与工作流虽然可以并发，运行状态却只显示在各自输入区，切换页面后不容易判断任务是否仍在执行；文档列表也缺少统计、筛选和明确的错误语义。

P0 优化聚焦以下结果：

1. 用户进入页面后能立即分清问答、工作流、关联图、文档和知识库。
2. 任意页面都能看见普通问答与工作流的独立运行状态。
3. 加载、空数据、错误、中断和完成都有明确反馈。
4. 回答中的标题、列表、代码、公式文本与引用具有稳定层级。
5. 点击引用后，正文与原文可以同时查看；文档列表也能直接打开完整原文。
6. 1440px 桌面、紧凑桌面、平板和 390px 手机宽度都可操作。

## 2. 技术栈与架构边界

前端继续使用 **HTML5 + CSS3 + 原生 JavaScript**，由 FastAPI `StaticFiles` 挂载，不引入 Node 构建、前端框架、字体 CDN 或运行时第三方脚本。

| 层 | 技术 | 用途 |
|---|---|---|
| 页面语义 | HTML5 | `nav`、`main`、`section`、`aside`、`form` 与 ARIA live region |
| 视觉系统 | CSS Custom Properties | 颜色、间距、圆角、宽度和字体 token |
| 布局 | CSS Grid + Flexbox | 三栏研究工作台、响应式导航、表格与工具栏 |
| 响应式 | Media Queries | 1260px 紧凑导航、1020px 原文抽屉、720px 顶部图标导航 |
| 请求 | Fetch API | 调用 `/api/v1`；统一解析服务端错误 |
| 中断 | AbortController | 普通问答与工作流各自中断浏览器等待 |
| 本地状态 | localStorage | 会话、活动会话、原文栏宽度与展开偏好 |
| 图形 | Canvas 2D | 零依赖力导向关联图 |
| 静态验证 | pytest + FastAPI TestClient | 页面与资源可访问、脚本挂载点完整且唯一 |
| 语法验证 | Node `--check` | CI 检查 `frontend/app.js` 语法 |

前端只渲染 API 返回的拒答、引用、步骤状态和文档状态，不在浏览器重复实现检索阈值、引用校验或工作流业务规则。

## 3. 页面架构

桌面端采用三栏研究工作台：

```text
┌──────────────┬────────────────────────────────────┬──────────────────┐
│ 功能导航      │ 当前视图标题、内容与操作              │ 原文核对          │
│              │                                    │                  │
│ 问答          │ 回答 / 工作流 / 关联图 / 文档 / 库    │ 可固定多条引用     │
│ 工作流        │                                    │ 可查看完整文档     │
│ 关联图        │                                    │                  │
│ 文档          │                                    │                  │
│ 知识库        │                                    │                  │
│              │                                    │                  │
│ 服务与任务状态 │                                    │                  │
└──────────────┴────────────────────────────────────┴──────────────────┘
```

- 左栏固定展示五个功能入口、本机服务状态，以及问答和工作流的两行独立状态。
- 中栏顶部展示当前视图名称和用途；URL hash 保存当前视图，可刷新或直接打开 `#docs`、`#map` 等入口。
- 右栏保留“答案正文 + 原文核对”的核心结构，可拖动调整宽度，也可收起。
- 1020px 以下右栏改为按需打开的覆盖抽屉，并默认收起，避免遮住移动端正文。

## 4. 视觉系统

界面使用低饱和冷灰画布、白色内容面、深墨绿主色和少量印章红。控件采用系统无衬线字体，回答与原文使用衬线字体，使操作与阅读形成稳定区分。

| Token | 值 | 用途 |
|---|---|---|
| `--canvas` | `#f4f5f2` | 应用背景 |
| `--surface` | `#ffffff` | 主要内容面 |
| `--ink` | `#182522` | 主文字 |
| `--ink-soft` | `#52615d` | 说明与次级信息 |
| `--line` | `#dbe2de` | 分隔与边界 |
| `--primary` | `#173f3d` | 导航、主按钮、图节点 |
| `--accent` | `#ad4a3c` | 引用、页面英文索引、注意状态 |
| `--success` | `#2c6b55` | 可检索与完成 |
| `--warning` | `#9a6421` | 等待处理与材料不足 |
| `--danger` | `#a63e36` | 请求失败与处理失败 |

阴影只用于输入坞、工具栏和主要内容面之间的层级，不参与业务状态表达。状态同时使用文字、颜色和圆点，避免只依赖颜色。

## 5. 问答、引用与工作流

### 5.1 问答

- 空会话展示产品说明和三个高等数学演示问题，点击后只填入输入框，由用户决定是否发送。
- `Enter` 发送，`Shift + Enter` 换行；输入框按内容自动增高。
- 请求条目显示当前等待说明和真实经过秒数。由于同步接口不返回服务端阶段，文案只说明“正在等待检索与生成”，不伪造精确后端进度。
- 结果显示引用数量、耗时、查询改写和拒答原因。
- 回答经“先转义、后格式化”的轻量渲染器处理，支持标题、段落、有序/无序列表、引用块、代码块、行内代码和公式文本；不执行回答中的 HTML。
- 回答下方汇总引用文档，正文编号和来源按钮均可打开右侧原文。

### 5.2 原文核对

- 同一来源块去重；再次点击会滚动到已打开材料并高亮对应引用。
- 多条引用可同时固定，计数同步显示在顶栏与右栏。
- 文档管理页的“查看”会在同一区域打开完整原文。
- 移动端点击引用时才打开抽屉；进入页面时不会用抽屉遮住内容。

### 5.3 工作流与并发状态

- 普通问答与工作流继续维护各自的 `AbortController` 和提交锁，同类请求一次只运行一个，两类请求可以同时运行。
- 左栏为两类任务分别显示 `运行中 mm:ss`，对应导航入口也显示脉冲圆点；切换视图后状态仍可见。
- 工作流等待区明确说明同步接口会在完成后一次返回结果。
- 完成结果使用时间线展示目标、检索语句、`answered / insufficient / error` 状态、分步结论与引用，最后单独显示综合结论。
- 点击“停止等待”只中断浏览器等待，界面明确提示服务端已经发出的模型调用仍可能继续。

## 6. 文档、知识库与关联图

文档页新增总数、可检索、处理中和需留意四项统计，并提供标题搜索、状态筛选、手动刷新、上传、重传、删除和完整原文预览。存在旧块的重传失败文档仍为 `ready`，界面显示“当前旧索引仍可使用；上次更新未完成”，避免把“可以检索”和“最近更新成功”混为一件事。`pending / processing` 存在时，页面每 2.2 秒自动刷新，离开文档页后停止轮询。

知识库页把创建表单和已有知识库并列展示。每个库显示说明、文档数量和“管理文档”入口；点击后会带着对应知识库进入文档页。

关联图保留四档阈值和 Canvas 力导向布局，新增加载遮罩、图例、统计与内联错误。力模拟收敛或页面隐藏后停止 `requestAnimationFrame`，拖动节点或重新进入页面时恢复，避免静止图仍持续占用主线程。

## 7. 状态、可访问性与验证

- 本机服务通过 `/ready` 同时检查 API 与数据库，并显示已连接或未连接；`/health` 仅用于进程存活检查。
- 关键动态区域使用 `aria-live`；图标按钮、引用和表单控件具有可读名称。
- 所有可操作元素保留 `:focus-visible`，引用支持 Enter 与空格键。
- `prefers-reduced-motion` 会关闭非必要动画。
- 手机布局经过 390×844 检查，页面无水平溢出，五个导航入口均保留。
- 自动化浏览器验证覆盖结构化回答、打开真实引用、问答与工作流同时在途、两项结果分别写回会话，以及移动端原文栏默认收起。
- pytest 额外核对 JavaScript 使用的每个 `getElementById` 挂载点在 HTML 中存在且唯一。

## 8. 后续边界

P0 没有改变同步 API 契约，因此工作流无法逐步从服务端推送真实进度，停止也不等于服务端取消。若后续实现 SSE 或任务队列，应将当前等待状态替换为服务端事件，并为每个步骤提供可取消任务 ID。会话仍保存在当前浏览器，跨设备同步和多 worker 持久化属于后续版本。
