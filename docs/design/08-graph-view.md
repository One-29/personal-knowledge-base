> 目标：像 Obsidian 的 graph view 一样，**直观看出笔记之间在语义上有多近**——
> 回答"我这个知识库里哪些内容其实是一类"。

## 1. 图的数据模型

| 元素 | 取什么 | 理由 |
|---|---|---|
| 节点 | **一篇文档** | 块级图在大库上会变成毛线团；文档级才可读（每篇笔记是人的思维单位） |
| 边 | 两篇文档的**语义关联强度** | 由块向量的跨文档近邻关系聚合而来 |
| 节点大小 | 块数（8 + chunks×1.6，上限 22px） | 内容量直观可见 |
| 边粗细/透明度 | 权重 | 一眼看出哪两篇最相关 |

## 2. 边的计算（`app/graph.py`）

```text
① 每个块在【其它文档】中找 top-k 最近邻（pgvector `<=>`，LATERAL 一次算完）
   WHERE c2.doc_id <> c.doc_id           ← 排除同文档（同篇笔记内部不算"关联"）
   相似度 < min_similarity 则丢弃          ← 过滤噪声
② 按文档对聚合：
   links      = 该对之间的近邻对数（关联"条数"）
   similarity = 这些近邻的平均相似度（关联"强度"）
③ 权重合成：weight = similarity × min(1, links / 2)
   —— 只有一条近邻的关联打折；两条以上逐渐饱和（避免块多的文档垄断）
④ 全局归一化到 0–1（除以最大权重），前端按权重画线宽
```

**实测结果**（5 篇笔记，阈值 0.30）——三篇 TCP 笔记之间的权重 0.94–1.00，
跨主题（TCP ↔ 操作系统/Python）只有 0.32–0.39：**语义聚类正确**。

## 3. 接口

```text
GET /api/v1/graph?kb_id=N&top_k=3&min_similarity=0.30
  200: {
    nodes: [{doc_id, title, chunks, chars}],
    edges: [{source, target, weight, links, similarity}],
    truncated: false            # 块数超过计算上限（400）时为 true，诚实标注结果不完整
  }
  404: 知识库不存在
  422: 参数越界（top_k>10 / 相似度>1）
```

## 4. 前端渲染（无依赖）

- **Canvas + 自实现力导向布局**：斥力（节点两两推开）+ 弹簧（有边相吸，权重越大越紧）+ 向心引力 + 阻尼；
- **交互**：鼠标悬停高亮该节点及其所有边并显示「标题 · 块数 · 字数 · 关联文档」；按住拖动可手动调整布局；阈值下拉（0.25/0.30/0.40/0.50）改变连边密度；
- **不引入图形库**：与前端"零构建"取向一致，代码量约 150 行。

## 5. 决策记录

### 决策 GR1：节点取文档而非块

- **决策**：图只画文档级关联。
- **备选**：块级图（更细，能看到"这一段和那一段像"）。
- **理由**：块级节点数 = 块总数（几百上千），视觉上是噪声；文档是人的思维单位，符合"看出哪些笔记是一类"的目标。
- **代价**：看不到块级细节——需要时通过问答的溯源栏核对具体段落。

### 决策 GR2：不做图数据库、复用向量索引

- **决策**：每次请求实时用 pgvector 近邻查询算图，不落图存储。
- **备选**：预计算并持久化邻接表（用图库/表存储）。
- **理由**：个人规模（几十篇、几百块）实时算 <1s；避免引入图数据库（03 §2.3 明确把 Graph RAG 排除在第一期外）。
- **代价**：大库（上千块）需要截断（`max_chunks=400` + `truncated` 标注）；真要做增量维护需另起设计。

### 决策 GR3：权重必须同时反映条数与强度

- **决策**：`weight = avg_similarity × min(1, links/2)`。
- **备选**：只用平均相似度（块多的文档会"到处都像"）；只用近邻对数（长文档垄断）。
- **理由**：两个维度都影响"这两篇是不是一类"的判断；饱和函数抑制块数效应。
- **代价**：权重是启发式合成，不是概率——它是**导航工具**，不参与检索、不影响回答（检索质量仍由 04/06 的链路与评估负责）。

## 6. 边界与后续

- 少于两篇文档时不显示图（没有"关联"可言），给出引导文案；
- 与检索链路完全解耦：图只读 chunks 向量，不改任何检索行为（防偏移）；
- 后续可做：把"点击节点 → 按该文档范围提问"打通成入口（现在图是只读观察工具）。
