> 本文把「文档先行、边界讲透、尽量简洁」固化成**可执行步骤**：每个阶段有明确产出与出口标准。
> 总原则：**先想清楚再动手；每份文档只回答它该回答的问题（§3 归属表）；写完能讲穿才算完。**

## 1. 总流程（一次项目走一遍）

```mermaid
flowchart TD
    S0[S0 项目设计文档<br/>01-requirements 需求·用户故事·流程·决策] -->|决策拍板 冻结| S1
    S1[S1 模块拆分文档<br/>02-modules 模块·边界·依赖] -->|边界讲透| S2
    S2[S2 数据模型文档<br/>03-data-model 表·DDL·状态机] --> S3
    S3[S3 检索链路文档<br/>04-retrieval 切分·召回·判定] --> S4
    S4[S4 建仓<br/>README + docs + 总功能 Issue] --> S5
    S5[S5 模块循环<br/>对每个 Mx: 填模板→Issue→开发→PR] --> S6
    S6[S6 收尾<br/>联调·评估(06)·CI/CD]
```

| 步骤 | 做什么 | 出口标准（DoD） |
|---|---|---|
| S0 项目设计文档 | 写需求：产品定位、用户故事（带验收）、业务流程、NFR、决策 | 全部需求层决策拍板；每个用户故事可测 |
| S1 模块拆分文档 | 切模块：划分判据、每模块「属于/不属于」边界、依赖无环 | 模块边界表与归属速查表评审通过；**无环** |
| S2 数据模型文档 | 表设计：ER、DDL 草案、状态机、存储选型 | 数据层决策拍板；DDL 可作迁移底稿 |
| S3 检索链路文档 | 检索四问：切分/向量化/召回/判定 | 检索层决策拍板；移交清单清空 |
| S4 建仓 | git init、GitHub 建仓、推 README+docs、建总功能 Issue | 仓库可 clone；文档链完整；链接可交 |
| S5 模块循环 | 对每个模块走一遍 §2 子流程 | 模块 DoD（§2）达成；台账记录 |
| S6 收尾 | 联调、06 评估、CI/CD、Review Bot、README 更新 | 端到端可运行；全链路文档与代码一致 |

## 2. 模块循环（S5 内部，每模块走一遍）

```text
填写 templates/module-design.md
   → 内容即 GitHub 子 Issue（挂在总 Issue 下）
   → 开发（小步提交）
   → 按模板 §5 验收清单自查（= PR 合并条件）
   → 提 PR 关联本 Issue → 评审 → 合并
   → 台账记一行（模板底部：日期/模块/Issue/PR）
```

模块 DoD：验收清单全勾、测试绿、设计无漂移、PR 关联 Issue、台账已记。

## 3. 内容归属表（什么内容写在哪——防越界、防重复）

**写之前先问：这条内容是「产品级行为 / 模块间关系 / 单模块设计」中的哪一层？**
**一个事实只在一处写全，别处一律引用不复制（单一事实原则）。**

| 内容类型 | 归属（唯一权威） |
|---|---|
| 端到端业务流程、用户故事、验收标准、NFR、需求层决策 | `01-requirements.md` |
| 模块划分、依赖方向、模块间协作（跨模块时序） | `02-modules.md` |
| 表结构、字段、约束、文档状态机、存储选型 | `03-data-model.md` |
| 切分/embedding/检索合并/防幻/拒答判定（含算法参数与决策） | `04-retrieval.md` |
| 单模块的功能定位、数据原型、接口契约、**模块边界对照**、验收清单 | 填 `templates/module-design.md`（= 子 Issue） |
| 文档写作格式规则（头部信息/决策格式/伪代码规范） | `docs/README.md` |
| 开发流程步骤本身 | 本文件（workflow.md） |

**判断规则**：单模块内部的接口与边界 → 模板；一涉及"模块 A 和 B 怎么协作"→ 02；一涉及"用户整个旅程"→ 01。模板 §4 只填本模块的边界对照，不重述 01/02。

## 4. 简洁原则（执行条款）

1. **每份文档动笔前 5 分钟**：用 §3 表确认它的读者与唯一职责；不属于它的内容一律不写或移交。
2. **字数护栏**：单份 ≤300 行；超过 = 拆错粒度（docs/README §6）。
3. **图先于文**：流程/结构先画图、配一句图注（结论先行）；画不出图注说明没想清楚。
4. **决策即记录**：拍板当场写决策记录（决策/备选/理由/代价），不留"当时怎么定的"悬念。
5. **收尾能讲穿**：每份文档合上后能口头复述结构与关键决策；卡壳处即下轮修订清单。
