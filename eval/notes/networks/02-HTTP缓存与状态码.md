# HTTP 缓存、状态码与连接复用

HTTP 是应用层请求—响应协议。客户端发送方法、目标、首部和可选消息体，服务端返回状态码、首部与响应体。`GET` 用于读取资源，语义上应当安全且幂等；`POST` 常用于提交或创建；`PUT` 表示以给定表示替换目标资源，通常具有幂等语义。幂等指同一请求执行一次或多次，对服务端最终状态的预期影响相同。

## 状态码分类

状态码第一位表示类别。`2xx` 表示成功，`200 OK` 常用于返回内容，`201 Created` 表示资源已创建，`204 No Content` 表示成功但没有响应体。`3xx` 用于重定向或缓存协商，`304 Not Modified` 告诉客户端继续使用本地副本。`4xx` 表示客户端请求有问题，例如 `400 Bad Request`、`401 Unauthorized`、`403 Forbidden`、`404 Not Found`；`5xx` 表示服务端未能完成有效请求，例如 `500 Internal Server Error` 与 `503 Service Unavailable`。

## 强缓存与协商缓存

强缓存由 `Cache-Control: max-age` 或 `Expires` 控制。在新鲜期内，浏览器可以直接使用缓存而不访问源站。协商缓存会向服务端携带验证器：`If-None-Match` 对应 `ETag`，`If-Modified-Since` 对应 `Last-Modified`。资源未变化时服务端返回 `304`，节省响应体传输；发生变化则返回新的 `200` 内容。`no-store` 表示不应存储，`no-cache` 表示使用前必须重新验证，并不等于完全禁止保存。

## 长连接与 HTTP/2

HTTP/1.1 默认复用 TCP 长连接，减少重复握手。单条 HTTP/1.1 连接上的请求仍可能受队头阻塞影响。HTTP/2 把消息拆成带流标识的帧，在一条连接上多路复用多个流，并使用 HPACK 压缩首部；一个流等待时，其他流仍可传输。不过它仍运行在 TCP 上，丢包可能造成连接层面的队头阻塞。
