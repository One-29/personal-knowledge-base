# DNS 解析与 IP 路由基础

DNS 把域名映射为 IP 地址或其他资源记录。浏览器通常先查自身缓存和操作系统缓存，再由本地递归解析器继续查询。递归解析器若没有缓存，会从根域名服务器获得顶级域服务器线索，再向权威域名服务器取得最终记录。客户端只向递归解析器提出一次递归请求；解析器替客户端完成后续迭代查询。

## 常见资源记录与缓存

`A` 记录保存 IPv4 地址，`AAAA` 保存 IPv6 地址，`CNAME` 为别名，`MX` 指定邮件交换服务器，`NS` 指定区域的权威域名服务器。每条记录带 `TTL`，解析器在 TTL 到期前可以复用缓存。较短 TTL 便于快速切换地址，但会增加查询量；较长 TTL 降低权威服务器负载，却让变更传播更慢。DNS 通常使用 UDP 53 端口，响应过大、区域传送或需要可靠传输时也会使用 TCP。

## 子网、网关与最长前缀匹配

IP 地址配合前缀长度确定网络部分。例如 `192.168.1.0/24` 的前 24 位是网络前缀。同一子网内的主机可通过 ARP 找到目标链路层地址；目标不在本地子网时，主机把数据报交给默认网关。路由器查询路由表时采用最长前缀匹配：能匹配目的地址的条目中，前缀越长越具体，因此优先级越高。

## TTL 与 ICMP

IP 首部中的 TTL 每经过一个路由器减一，降到零时路由器丢弃数据报并通常返回 ICMP 超时报文，防止路由环路让报文永久循环。`traceroute` 正是逐步提高 TTL，根据沿途返回的 ICMP 超时消息推断路径。ICMP 还用于差错报告和诊断，但它不负责修复丢包；端到端可靠性通常由 TCP 等上层协议实现。
