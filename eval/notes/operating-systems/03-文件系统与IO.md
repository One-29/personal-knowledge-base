# 文件系统与 I/O

文件系统把持久化设备上的块组织为文件和目录。文件描述符是进程打开文件后获得的小整数，它引用内核中的打开文件表项；表项保存当前偏移、访问模式和底层 inode 等信息。父子进程可以继承描述符，多个描述符也可能引用同一个打开文件表项，因此共享文件偏移。

## inode、目录项与硬链接

类 Unix 文件系统用 inode 保存文件类型、权限、大小、时间戳以及数据块位置，但 inode 本身通常不保存文件名。目录是一张“名称到 inode 号”的映射。硬链接是在目录中新增一个指向同一 inode 的名称，删除其中一个名称只减少链接计数；链接计数归零且没有进程打开时，数据才可回收。符号链接则是独立文件，内容保存目标路径，可以跨文件系统，但目标删除后会成为悬空链接。

## 缓冲、页缓存与 fsync

普通写操作往往先进入内核页缓存，随后由系统异步回写设备，所以 `write` 成功不等于数据已经到达稳定介质。`fsync` 要求把指定文件的脏数据和必要元数据刷新到持久化设备；需要保证新文件名本身持久时，还应同步其父目录。顺序访问便于预读和批量写回，随机小 I/O 更容易受寻道或闪存映射开销影响。

## 阻塞、非阻塞与 I/O 多路复用

阻塞 I/O 在操作不能立即完成时挂起调用线程。非阻塞描述符会立即返回“稍后再试”，调用者若不断轮询会浪费 CPU。`select`、`poll`、`epoll` 等 I/O 多路复用机制让一个线程等待多个描述符的就绪事件。就绪只表示下一次读写大概率不会阻塞，并不保证一次操作传完全部数据，程序仍要处理部分读写和连接关闭。
