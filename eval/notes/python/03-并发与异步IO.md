# Python 并发、线程与异步 I/O

并发表示多个任务在时间上交错推进，并行表示多个任务在同一时刻真正执行。CPython 的 GIL 使一个进程内通常只有一个线程执行 Python 字节码，因此线程不适合加速纯 Python 的 CPU 密集计算；阻塞 I/O 会释放 GIL，所以线程仍适合网络请求、文件等待等 I/O 密集任务。多进程拥有独立解释器和 GIL，可以利用多个 CPU 核心，但进程间传输数据需要序列化，启动和通信成本更高。

## 竞态条件与锁

即使有 GIL，多步读—改—写操作也不一定原子。两个线程同时更新共享状态可能丢失修改，这称为竞态条件。`threading.Lock` 用互斥区保护不变量；持锁范围过大降低并发度，锁顺序不一致还可能产生死锁。队列通过消息传递减少直接共享状态，通常比到处加锁更容易推理。

## asyncio 事件循环

`async def` 调用后产生协程对象，必须由事件循环调度或被 `await`。协程执行到 `await` 一个尚未完成的 I/O 时主动让出控制权，事件循环转去运行其他就绪任务。它用单线程管理大量等待型连接，避免“一条连接一个线程”的栈和调度成本。协作式调度要求任务主动让出；在协程里直接执行长时间 CPU 计算或同步阻塞调用会卡住整个事件循环。

## 取消与结构化清理

取消 asyncio 任务会在下一个可取消等待点抛出 `CancelledError`。协程应使用 `try/finally` 释放锁、连接和临时资源，然后继续传播取消；吞掉取消会让上层误以为任务已经停止。`asyncio.TaskGroup` 把相关子任务放在同一生命周期中，一个任务失败时取消其余任务，并在退出上下文前等待清理完成，减少遗留后台任务。
