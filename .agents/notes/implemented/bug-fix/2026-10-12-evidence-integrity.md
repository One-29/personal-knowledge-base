# Agent Note: 完整原文与工作流出处一致性

Status: implemented

## Problem

定长边界可能拆散否定、条件或指代，使片段脱离原文含义。工作流将出处问题重新送入检索时，也可能在前一步已有依据的情况下因措辞不同而拒答。仅验证引用编号存在，不能保证片段仍属于同一份已发布原文。

## Decision

检索块按 Markdown 结构与完整语句组合，保留原文字符锚点。达到 L1 回答线后，从已发布索引补齐规则识别的必要上下文；补充块不增加向量分数、不改变原始相关性判断。缺少必要前提或超出预算时返回待核对，而不是截短后生成。

工作流将知识查询与出处核对分开：出处步骤只复用依赖步骤的正式原文和必要上下文，并核对问题对象、来源编号和连续原文摘录。回答发布前重新核对来源有效性；前端按文档组织引用，保留不同片段的真实位置。

单文档更新索引通过版本化任务显式触发，绕过同内容上传的幂等跳过，但不绕过原文完整性和任务版本校验。新索引成功发布前保留旧索引，不自动重建用户知识库。参数和处理规则分别由[检索设计](../../../../docs/design/04-retrieval.md)、[工作流设计](../../../../docs/design/05-agent-workflow.md)和[维护说明](../../../../docs/operations.md)维护。

## Alternatives considered

**仅增大固定重叠。** 增加重复字符不能保证边界保留完整否定或条件，因此重叠改为完整末句预算，并另行恢复必要上下文。

**一句对应一个向量。** 单句粒度仍可能丢失跨句主语，并增加块数和检索噪声；当前按多句组块，不更换向量模型和存储架构。

**每个出处问题重新检索。** 同一结论的出处会受到查询措辞和阈值的再次影响；已有正式依据时直接核对依赖原文，新知识问题仍正常检索。

## Consequences

超长且不可安全拆分的结构会明确失败，需要用户调整原文结构或配置。上下文补全增加数据库读取及部分生成输入；规则只能保守识别常见语法，不能保证任意自然语言都语义完整。索引重建产生向量服务调用，成功后替换 chunk id，不自动迁移历史回答。

## Testing

受控回归覆盖否定与条件、整句重叠、结构保护、原文偏移、必要上下文、来源变化、工作流依赖、同内容重建、失败保留旧索引和图片字节一致性。已有本地证据为 182 项后端测试通过，补充的 Vault、入库、证据分级、SSE 和前端静态检查另有 39 项通过；两组选定测试共 98 项依赖 PostgreSQL 或其应用生命周期，未在本地完成。34 项前端测试、类型检查和构建通过。测试使用受控模型，不代表真实模型语义评估；大文档性能、重新切分后的真实召回率和 PostgreSQL 完整回归需单独验证。
