# Agent Note: Validate frontend data without rebinding damaged history

Status: implemented

## Problem

通用 JSON 请求以类型断言代替运行时检查，工作流、关联图、文档等入口可以接收错误字段。SSE 已有检查，但部分数字仅要求有限值，且未注册回调时会跳过元数据和增量检查。历史解析把非法来源 ID 补为 0，随后去重和连续编号可能改变正文引用的目标。问答输入框允许 1000 个 UTF-16 单元，后端只接受 500 个 Unicode 码点。

## Decision

`frontend/src/validation/` 按业务拆分纯解析器。`api.ts` 接收 `unknown` 并要求调用方提供解析器；204/205 使用单独无正文方法。SSE 复用回答与来源解析器，保留顺序、完整性、中断和错误检查。错误标明字段路径；JSON 数字不做字符串强制转换，DOM 编号转换由 `validation/input.ts` 明确负责。

`history/conversations.ts` 和 `history/sources.ts` 在本地数据进入内存时解析一次。存储管理只负责读写与副本，不在每次读取供渲染时重新校验。损坏来源成为独立不可用记录，不制造 chunk ID；相同编号的冲突和同一 chunk 的冲突快照均隔离。正文和有效快照保留，坏记录不压缩编号。健康旧工作流按真实 chunk 身份迁移局部编号，并预留正文中尚无来源的编号，防止新分配的来源占用它。

兼容依据是仓库旧实现：`9d15b8d` 的回答已有 `refused`、`session_id`、`search_query` 和 `refusal_reason`，尚无灰区的 `status`、`evidence`、`possible_sources`；图片和来源依赖字段也有明确的加入过程。缺失新增字段可以迁移，非法现有字段不能伪装成成功回答。来源详情 404 时保留有效快照回退，其他故障仍报错。

前后端统一清理首尾空白并按 Unicode 码点限制为 500。验证先于清空输入和创建任务。`history/context.ts` 在准备请求时排除超限旧问题及损坏来源轮次，展示记录不删除。图片区间按后端相交规则解析，显示时限制文本替换范围，不修改原图。

## Alternatives considered

**把全部校验放入 `api.ts`。** 会让网络传输依赖所有业务字段，SSE 和历史恢复仍需重复实现。共享基础规则和业务解析器保留了职责分离。

**把坏 ID 转成数字、补 0，或删掉后连续编号。** 会掩盖损坏，也可能把原正文的引用标记绑定到另一份文档。不可恢复来源必须显式不可用，不能猜测身份。

**拒绝整条历史记录。** 来源损坏不代表所有正文和其他快照都无效，因此保留可读内容并隔离有问题的来源；语义可靠性不能靠这种恢复来保证。

**只把 HTML `maxlength` 改为 500。** HTML 使用 UTF-16 单元，500 个常见 emoji 会被当作 1000；发送前按码点检查才能与 Python 一致。

## Consequences

新增的字段校验会明确暴露以前被静默接受的异常响应，需要后端字段变更同步更新对应解析器。没有新增浏览器运行时依赖。有效来源维持点击核对和历史快照能力；缺失、已损坏且无法恢复的编号只能标记不可用，不能凭剩余数据还原原始映射。原图片文件已删除时，保存的图片地址不能重新生成图片字节。

这些检查保证数据结构和引用映射的合法性，不判定回答是否在语义上被原文支持，也不消除模型幻觉。分块、召回、生成及语义证据判断不在本次修改范围。

## Testing

先添加失败用例，再修复：非法 SSE ID、多个损坏历史来源错合并、Python 空白输入、冲突快照和旧问题超限均有回归覆盖。前端检查包含类型检查、全部 Vitest 测试和生产构建；后端使用仓库 pytest 配置、隔离的 PostgreSQL `knowbase_test` 与 SQLite 场景。空库迁移与 `alembic check` 另在专用临时数据库执行。

Windows 到 WSL 数据库的连接在本机超时，完整后端测试改用 WSL 内临时 Python 3.13 容器，测试 provider 不调用真实模型服务。前端 DOM 替身测试不代表浏览器视觉测试；Windows 冻结包启动由仓库的 GitHub CI 单独检查。

本次本机验证：`npm run frontend:check` 通过，13 个测试文件、102 项测试；完整 pytest 497 项通过。最终前端构建后的静态资源冒烟 7 项通过，空库迁移及模型差异检查通过。pytest 有 1 条 Starlette/httpx 弃用警告，无失败或跳过。
